    B now equals A            : True
    -> the divergence is fully explained by the timestamp field, nothing else.

  CONSEQUENCE - is the timestamp authenticated by the proof-of-work?
    valid_proof on the block as mined                 : True
    timestamp :=            0.0   valid_proof still True  and hash_block changed: True
    timestamp :=            1.0   valid_proof still True  and hash_block changed: True
    timestamp :=   2000000000.0   valid_proof still True  and hash_block changed: True
    timestamp :=           -1.0   valid_proof still True  and hash_block changed: True
    -> a block's recorded time can be set to any value at all and the
       proof-of-work still validates.  The PoW covers the ledger's contents
       but not its clock; only the *link* into the next block notices.

  CONTROL - valid_proof must fail when a field it DOES cover is changed.
  Without this, the result above would only show the check is vacuous.
    nonce + 1        -> valid_proof = False
    index + 1        -> valid_proof = False
    prev hash + 'a'  -> valid_proof = False
    txs + [1]        -> valid_proof = False
    -> the check is not vacuous; it binds every field in the preimage.
       The timestamp is absent from the preimage, not merely unchecked.

==============================================================================
WHAT THIS DOES AND DOES NOT EXPLAIN
==============================================================================
  FINDING 1 is a defect in the measurement protocol, not in the code. The
  spread between 0.2403 s and 1.5543 s is ordinary geometric variance that the
  prescribed estimator cannot resolve at n = 3. It is NOT caused by FINDING 2,
  and this report does not claim that it is.

  FINDING 2 is a defect in the provided scaffold, visible only in multi-node
  behaviour: identical work, divergent identity, no canonical genesis. It does
  not affect a single node's timing, and the 6.47x spread is not evidence of it.

  They are independent, and they are reported as two findings.
